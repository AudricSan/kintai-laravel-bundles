# hiring-report

🌐 **English** · [Français](#français)

Official "Hiring Report" bundle for [Kintai](https://github.com/AudricSan/kintai-laravel) — browse, edit, and export hiring reports per store as PDF. The report itself is auto-generated by Kintai Core on every employee creation regardless of whether this bundle is installed; this bundle only provides the browsing/editing/PDF UI (`/admin/reports/hiring`, `/admin/stores/{id}/reports/hiring/*`).

Part of [kintai-laravel-bundles](https://github.com/AudricSan/kintai-laravel-bundles), the official bundles of Kintai on Laravel: views are Blade templates, and the bundle requires bundle contract `^1.31`. Its tests, CI and releases are shared with the other bundles of that repository (see its README).

## Installing

From a running Kintai instance, as the Owner: `/admin/bundles/market` → find "Hiring Report" (listed as official, from the official Kintai registry) → Install.

Manual installation isn't supported: Kintai never does `git clone`/`pull` for bundles (many shared-hosting environments have no `git` CLI available to PHP) — it always downloads a tagged GitHub Release's zipball through `BundleInstallerService` (here the `hiring-report-vX.Y.Z` release of kintai-laravel-bundles, of which only the `hiring-report/` folder is installed).

## Structure

```
bundle.json          # manifest — slug, version, Kintai core compatibility, entry class
src/
  HiringReportBundle.php                      # kintai\Bundles\Installed\HiringReport\HiringReportBundle
  Controllers/Web/AdminHiringReportController.php
Views/                # list (all-stores + per-store), form, detail, PDF template
lang/{en,fr,ja}.json  # bundle-specific translation keys
routes.php            # loaded by HiringReportBundle::register() via loadRoutesFrom()
```

## Releasing a new version

Releases are cut from the root of [kintai-laravel-bundles](https://github.com/AudricSan/kintai-laravel-bundles#releases): bump `version` in `bundle.json` only when opening a new `X.Y` line, add your changes to `CHANGELOG.md` under `## [Unreleased]`, and merge into a channel branch; the release workflow tags `hiring-report-vX.Y.Z` and publishes the GitHub Release.
