# kintai-bundle-hiring-report

🌐 **English** · [Français](#français)

Official "Hiring Report" bundle for [Kintai](https://github.com/AudricSan/Kintai) — browse, edit, and export hiring reports per store as PDF. The report itself is auto-generated by Kintai Core on every employee creation regardless of whether this bundle is installed; this bundle only provides the browsing/editing/PDF UI (`/admin/reports/hiring`, `/admin/stores/{id}/reports/hiring/*`).

This bundle used to live inside the main Kintai repository (`src/Bundles/HiringReport/`); it's now distributed independently, the same way any third-party bundle would be — see [docs/creating-a-bundle.md](https://github.com/AudricSan/Kintai/blob/main/docs/creating-a-bundle.md) in the main repository for the full distribution model (manifest, registry, installer).

## Installing

From a running Kintai instance, as the Owner: `/admin/bundles/market` → find "Hiring Report" (listed as official, from the official Kintai registry) → Install.

Manual installation isn't supported: Kintai never does `git clone`/`pull` for bundles (many shared-hosting environments have no `git` CLI available to PHP) — it always downloads a tagged GitHub Release's zipball through `BundleInstallerService`.

## Structure

```
bundle.json          # manifest — slug, version, Kintai core compatibility, entry class
src/
  HiringReportBundle.php                      # kintai\Bundles\Installed\HiringReport\HiringReportBundle
  Controllers/Web/AdminHiringReportController.php
Views/                # list (all-stores + per-store), form, detail, PDF template
lang/{en,fr,ja}.json  # bundle-specific translation keys
routes.php            # loaded by HiringReportBundle::register() via loadRoutesFrom()
```

## Releasing a new version

`main`, `alpha`, and `beta` are protected branches — no direct push. Releases
are cut by opening a PR into the target channel branch and merging it once CI
is green; you never tag or run `gh release create` by hand. See
[CONTRIBUTING.md](CONTRIBUTING.md) and [CLAUDE.md](CLAUDE.md#release-process)
for the full flow.

1. Bump `version` in `bundle.json` by hand only when opening a new `X.Y` line.
2. Add your changes to `CHANGELOG.md` under `## [Unreleased]`.
3. Open a PR targeting `alpha` (new work), `beta`, or `main`, and merge it once CI passes.
4. `.github/workflows/release.yml` computes the tag (`vX.Y.Z` on alpha/beta, `vX.Y.0` on main) and creates the GitHub Release automatically — Kintai's installer reads its `zipball_url` directly, nothing else to build or upload.
